# Сетка (setka.ru) — разбор источника, 2026-09-12

Деловая соцсеть от hh.ru, позиционируется как российский аналог LinkedIn.
Задача разбора: можно ли брать оттуда HR-вакансии в наш бот. Всё ниже — живые замеры
с локальной машины, не пересказ документации. Публичного API у Сетки нет; официальной
документации разработчика тоже (у hh она есть — `dev.hh.ru`, но она про hh, не про Сетку,
и для соискателей закрыта с 2026 года).

---

## 1. Итог одной строкой

Сетка **парсится без авторизации** — сервер отдаёт готовый HTML, есть публичные ленты с
пагинацией и полный sitemap. Внутри есть **готовая HR-лента вакансий** — сообщество
«HR Вакансии», где к каждому посту прикреплена карточка вакансии hh.ru. Но это сообщество
**молчит с 2026-05-29**, а поиск и лента подписок закрыты логином. Значит ценность Сетки
не в дубле hh-вакансий, а в постах-«ищу человека в команду», которых на hh нет.

---

## 2. Что за сервис и есть ли API

- Сайт: `https://setka.ru`, CDN ассетов `https://cdn-assets.setka.ru`, картинки `https://cdn.setka.ru`
- **Публичного API нет.** `https://api.setka.ru` отвечает (Go-сервер, `404 page not found`,
  `Content-Type: text/plain`) на `/`, `/v1`, `/api/v1`, `/health`, `/docs`, `/openapi.json` —
  то есть хост живой, но ручки наружу не смотрят или требуют других путей/токена.
- **Фронт на htmx**, не на React/Next. В бандлах (`cdn-assets.setka.ru/setka-web/static/js/…`)
  нет ни одного `/api/*`-пути: подключены `htmx.min.js`, `htmx-json-enc`, `htmx-response-targets`.
  Сервер отдаёт **куски HTML**, а не JSON. Ни `__NEXT_DATA__`, ни `window.__INITIAL_STATE__`,
  ни GraphQL, ни `application/ld+json` на странице поста нет.
- Следствие: технически это ровно наш случай с hh.ru — парсинг разметки. Только разметка
  проще: htmx-эндпоинты сами перечислены в атрибутах `hx-get` на странице.

## 3. Что доступно без логина (проверено)

| URL | Ответ | Что даёт |
|---|---|---|
| `/posts/<uuid>` | 200, ~320 КБ | пост целиком: текст, автор, вложенная карточка вакансии |
| `/communities/<uuid>` | 200, ~105 КБ | описание сообщества + эндпоинт его ленты |
| `/communities/<uuid>/load-more-posts?page=N&feed_id=<uuid>` | 200 | **5 постов на страницу**, пагинация работает анонимно |
| `/posts/<uuid>/load-more-posts?page=N&feed_id=<uuid>` | 200 | 5 «похожих» постов, алгоритмическая лента |
| `/posts/<uuid>/comments/load-more?cursor=…` | 200 | комментарии |
| `/users/<uuid>` | 200 | профиль |
| `/search?q=…` | **302 → `/login`** | поиск только под логином |
| `/feed` | 404 | общей ленты по этому пути нет |

Заголовок `HX-Request: true` для `load-more-posts` не обязателен, но вежливее — так ходит
сам сайт.

**robots.txt** (2026-09-12): `Disallow: *?*` (любые URL с query-строкой), `/accounts/*`,
`/feed/subscriptions*`, `/feed/questions*`, `/channels/*`, `/chats*`, `/login*`, `/onboarding*`.
То есть `load-more-posts?page=…` формально под запретом для краулеров, а `sitemap.xml` и
страницы `/posts/<uuid>` — разрешены. Это вопрос политики, а не техники: решать владельцу.

## 4. Sitemap — полный публичный индекс

`https://setka.ru/sitemap.xml` — sitemapindex на **2377 чанков**:

| Тип | Чанков | Примерно записей |
|---|---|---|
| `/posts/sitemap/…` | 558 | ~1,1 млн постов |
| `/users/sitemap/…` | 1813 | ~3,6 млн профилей |
| `/communities/sitemap/…` | 6 | ~18 тыс. сообществ |

Чанк постов — до ~1965 URL, у каждого `<lastmod>` (в свежих чанках — сегодняшняя дата,
`changefreq: hourly`). Курсор чанка — base64 от `{"last_id": "<uuid>"}`, то есть нарезка
идёт **по id, не по дате**: «последний чанк» — не «самые свежие посты».

## 5. Дата поста берётся из его id — фетчить страницу не нужно

Свежие посты используют **UUIDv7**: первые 48 бит — миллисекунды Unix-времени.

```python
def post_time(uuid_str):
    if uuid_str[14] != '7':      # версия UUID
        return None              # старые посты — UUIDv4, времени в id нет
    ms = int(uuid_str.replace('-', '')[:12], 16)
    return datetime.fromtimestamp(ms / 1000, timezone.utc)
```

Проверено: `019b0d90-3081-7f00-…` → 2025-12-11 13:18 UTC, все 20 постов главной страницы
(2026-09-10…11) декодировались верно. Посты старше ~2025 года — UUIDv4, там так не выйдет.

Это ровно то, что нужно для гейта свежести: можно отсеять старьё **по списку из sitemap**,
не скачивая ни одной страницы.

## 6. Вакансии внутри Сетки

### 6.1. Готовое сообщество «HR Вакансии»

`https://setka.ru/communities/018fc596-c5af-4388-b5a8-1f7ee20e58cc`
Описание: «Вакансии в сфере HR: подбор и адаптация, партнерство, обучение, развитие, оценка».

Лента отдаётся анонимно, 5 постов на страницу. Замер (5 страниц, 25 постов):
**в каждом посте — ровно одна прикреплённая вакансия hh.ru**, всего 25 из 25.

Карточка вакансии в разметке поста выглядит так:

```
вакансия  Ведущий менеджер по подбору персонала / HRBP
От 3 до 6 лет, от 120000 ₽, Москва
Международный Центр Здоровья
href="https://hh.ru/vacancy/133599906?from=share_ios&utm_source=setka&utm_medium=referral"
data-analytics-event-value='{"event_name":"view_vacancy_click", ...}'
```

То есть готовые поля: должность, опыт, зарплата, город, работодатель и **id вакансии hh**.

⚠️ **Лента мёртвая**: самый свежий пост — 2026-05-29, старейший в выборке — 2026-05-15.
Три с половиной месяца тишины. В описании сообщества редакция зовёт в свой Telegram-канал
(`t.me/+G18cBYZSOLJkNzVi`) — похоже, активность уехала туда.

### 6.2. Обычные посты

В случайной выборке 40 постов алгоритмической ленты — 3 поста про наём (все IT: архитектор,
Engineering Manager, Tech Lead + DevOps), HR-вакансий не попалось (выборка была смещена
темой стартового поста). Формат — свободный текст «снова вакансия…», иногда с карточкой hh,
иногда без.

### 6.3. «Сетки» (`/networks/<uuid>`) — живой канал, в отличие от сообщества

Сетка группирует людей по паре «роль × компания»: «HR BP, Лента», «менеджеры по персоналу,
ANCOR», «лиды подбора персонала, E-commerce». Страница публична, лента отдаётся анонимно:

```
/networks/<uuid>                         → страница сетки + виджет участников
/networks/<uuid>/feed/load-more?working_type=working_now&feed_id=<uuid>   → лента, 5 постов
/networks/<uuid>/members                 → участники, 50 профилей на странице
```

Замер трёх HR-сеток (2026-09-12):

| Сетка | Постов | Вложений hh | Про наём | Свежесть |
|---|---|---|---|---|
| лиды подбора персонала, E-commerce | 5 | 2 | 2 | 2026-09-04 … 2026-09-11 |
| HR BP, Лента | 5 | 0 | 0 | 2026-09-02 … 2026-09-10 |
| менеджеры по персоналу, ANCOR | 4 | 6 | 3 | 2026-05-27 … 2026-08-01 |

Здесь и лежит то, чего нет на hh. Примеры живых постов:

- «Открыта позиция финансового аналитика. **Перед откликом сначала напишите мне**»
  (+ прикреплённая карточка hh) — 2026-09-09;
- «Ищем продюсеров-экспертов, которые хотят применить свой опыт в новой сфере…» — без
  карточки hh вообще, только текст и автор;
- «Компания — системный интегратор — ищет в свою команду Старшего инженера АСУ ТП…».

То есть формат ровно тот, ради которого Сетку и стоит трогать: вакансия от конкретного
человека, часто с просьбой писать напрямую.

⚠️ Пагинация ленты сетки не разобрана: параметр `&page=N` я приписал вручную, и ответ
похож на ту же первую страницу. Нужно посмотреть, как листает сам сайт (курсор? другой
параметр?). Это первое, что проверять в следующий заход.

- `/channels/*` — закрыто в robots, содержимое не смотрел.
- Мобильное приложение — вероятно, ходит в JSON API (в robots есть `af_xp`, `appmetrica`,
  `deep_link` — следы AppsFlyer/AppMetrica). Перехват трафика приложения покажет настоящие
  ручки, если понадобится.

## 7. Что это даёт боту — и чего не даёт

**Не даёт:** дубли hh. Вакансии из «HR Вакансий» — это те же `hh.ru/vacancy/<id>`, которые
наш бот и так видит по осям. Гонять второй источник ради того же — минус.

**Даёт (потенциально):**
1. **Посты «ищу человека к себе в команду»** — их на hh нет вообще. Это вакансии от первых
   лиц, часто до публикации на hh.
2. **Сигнал качества компании и человека** — автор поста виден, у него профиль, должность,
   компания. Можно скрещивать со скорингом работодателя.
3. **Раннее обнаружение**: пост в Сетке появляется раньше, чем вакансия доходит до выдачи hh
   (гипотеза, не замерено).

**Цена:** фильтровать придётся по свободному тексту, а не по структурированным полям.
`snippet`-подобного описания нет, зато текст поста полностью в HTML — в отличие от hh,
где в списочной выдаче описание пустое.

## 8. Что мешает прямо сейчас

1. **Поиска без логина нет** (`/search?q=` → `/login`). Значит «найти все посты про HRD»
   в лоб нельзя — только обход лент конкретных сообществ/сеток или прогон sitemap.
2. **Sitemap огромный** — 1,1 млн постов. Полный обход не для сервера с 1 ГБ RAM.
   Реалистично: держать список из 5–20 нужных сообществ/сеток и опрашивать их ленты.
3. **Профильное сообщество простаивает** с мая 2026. Нужно найти живые HR-ленты
   (см. `/networks/` выше), иначе источник пустой.
4. **robots.txt** закрывает URL с query-строкой, а пагинация лент — именно такая.
5. **Авторизация** сняла бы ограничения (поиск, лента подписок), но для входа нужен номер
   телефона; это отдельное решение владельца, плюс риск блокировки аккаунта.

## 9. Следующие шаги (черновик, до обсуждения)

1. Разобрать пагинацию ленты сетки (`/networks/<id>/feed/load-more`) — как листает сам сайт.
2. Найти **все** HR-сетки: сейчас три штуки нашлись через поисковик. В sitemap сеток нет
   (только posts/users/communities), значит нужен другой путь — например, собирать
   `/networks/<uuid>` со страниц профилей HR-специалистов.
3. Прогнать по sitemap сообществ (18 тыс., 6 чанков) и собрать названия — найти живые
   HR-сообщества.
3. Замерить на живой HR-ленте: сколько постов в сутки, какая доля — реальные вакансии,
   какая задержка относительно появления на hh.
4. Решить по политике: ходим ли по URL с query-строкой вопреки robots, или только через
   sitemap и страницы постов.
5. Если источник окупается — писать `fetch_setka()` в `web/utils.py` по образцу
   `fetch_habr_career` / `fetch_superjob`, нормализовать в тот же формат вакансии,
   и пускать через существующий `hr_filter.decide`.
